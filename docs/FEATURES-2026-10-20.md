# Stabilizace a rozšíření (2026-10-20)

Výchozí větev: `main`, commit `81947df18d02d54ac21dee27db3ce2e657000959`.
Tento branch je **experimentální** a nemá se slučovat do `main`, dokud
neprojde kompilací všech platforem a skutečnými testy klimatizace.

## Zachováno na výslovné přání
- Konfigurační AP WiFiManager zůstává **bez hesla**.
- Výchozí WebUI přihlašovací údaje zůstávají **admin / admin**.
- Piny RX/TX zůstávají beze změny; opravovány jsou jen zavádějící komentáře.
- Ověřená šestirámcová UART SYN/ACK sekvence, 9600 8E1 a časování zůstávají
  **beze změny**. Nikdy nenasazovat alternativní neblokující UART parser
  bez laboratorních testů a zaznamenaných rámců.

## Provedené změny
1. BOOT tlačítko spouští WiFiManager v neblokujícím režimu. ESP dál
   průběžně obsluhuje HVAC během otevřeného konfiguračního AP.
   Konfigurační portál se sám uzavře po 5 minutách.
2. WiFiManager již nevkládá uložená MQTT, OTA a Telnet hesla do HTML
   formuláře; prázdná políčka ponechávají původní hodnoty.
3. MQTT publish používá buffer 2048 B a kontroluje návratové hodnoty;
   monitoring počítá úspěšná připojení.
4. Tovární reset, změny konfigurace, servisní příkazy, restart a ovládání
   používají autentizovaný CSRF token. Token se regeneruje při startu ESP.
5. Při neúspěšné/abortované aktualizaci firmware se obnovuje provoz
   Modbus bez opakované registrace existujících holding registrů.
6. UART diagnostika považuje známý, nezměněný status za platný rámec
   a odděluje zaznamenané změny stavu od rozpoznaných rámců.
7. Modbus existující adresy 0..11 ponechány, nové diagnostické adresy
   100..112 mají samostatnou dokumentaci, aktualizace každou sekundu.
8. Home Assistant MQTT Discovery: opt-in konfigurace v Nastavení, climate
   entity s režimy, teplotami, ventilátorem a filtrováním nepodporovaných
   funkcí (swing). Discovery publikuje retained konfiguraci, při vypnutí
   odešle retained smazání; MQTT Last Will nadále signalizuje stav spojení.
9. Capability Manager: neznámá/podporovaná/nepodporovaná funkce,
   automatické **pozorování protokolové podpory**, manuální přepsání,
   perzistence v oddělené EEPROM konfiguraci s CRC. Absence odpovědi
   není automatickým důkazem nepodporované funkce.
10. Přepínání čeština/angličtina (samostatné `LocaleCs.h` a `LocaleEn.h`),
    dostupné v hlavním dashboardu a servisním rozhraní, jazyk uložen lokálně
    v prohlížeči.
11. Tlačítko Restartovat v nastavení volá autentizovaný POST
    `/api/restart`, návrat HTTP 202 a restart po krátké prodlevě.
12. Záloha a obnova konfigurace ve webovém rozhraní. Backup má schema 1,
    nikdy neobsahuje uložená hesla ani Wi-Fi přihlašovací údaje.
13. Automatické sestavení přes PlatformIO pro ESP8266 D1 mini,
    ESP32 a ESP32-C3. U ESP32 je použita partition `min_spiffs.csv`,
    aby byl prostor pro firmware i dvě OTA aplikace (4MB flash).

## API
- `GET /api/security` vrací per-boot anti-CSRF token po Basic autentizaci.
- `POST /api/restart` restartuje pouze ESP, nikoli klimatizaci.
- `GET /api/extensions` načítá nastavení HA Discovery a Capability Manageru.
- `POST /api/extensions` nastavuje `discovery=0|1` a/nebo
  `feature=<key>&status=0|1|2`.
- `GET /api/metrics` vrací diagnostiku Wi-Fi, MQTT, UART a paměti.
- `GET /api/config/backup` exportuje nesenzitivní konfiguraci.
- `POST /api/config/import` přijímá JSON v parametru `backup`.
- `GET /lang/cs.json`, `GET /lang/en.json` vrací oddělené překlady
  (kompilované ze samostatných PROGMEM hlaviček).

Všechny výše uvedené POST endpointy kromě systémové firmware aktualizace
používají parametr `csrf` získaný z `GET /api/security`, příslušné
endpointy navíc kontrolují `X-Requested-With`. Formulář firmware uploadu
předává CSRF token a konečný handler jej ověřuje před restartem.

## Známá omezení
- Captive AP zůstává otevřené bez hesla na výslovné přání. **Není bezpečné
  používat v blízkosti nedůvěryhodných osob**, byť uložená hesla nejsou
  předvyplněna.
- WebUI má na výslovné přání výchozí účet `admin/admin`; nemá být
  vystaveno do veřejného internetu. HTTP Basic bez TLS neposkytuje ochranu
  přenášených hesel proti odposlechu.
- Příchozí Toshiba UART checksum **není aktivně verifikován**: algoritmus
  je potřeba nejprve potvrdit na reálných RX vzorcích. Není bezpečné
  nasadit nepodložené odmítání rámců.
- Capability Manager nezná mechanické provedení funkcí: stav „podporováno“
  při automatické detekci znamená „protokol funkci hlásí“, nikoliv
  že se lamely fyzicky pohnuly.
- Home Assistant Discovery vyžaduje existující MQTT broker dostupný v
  LAN a zapnuté MQTT; stav brokera nemůže být garantován pouze build testem.
- Záloha/export neobsahuje hesla, Wi-Fi konfiguraci ani uložené OTA binárky.
- Jazykové slovníky postupně pokrývají statické prvky dashboardu a servisu;
  některé starší konzolové/diagnostické věty zůstávají česky.
- Port Modbus TCP zůstává standardně 502, informační hodnota `modbusPort`
  není runtime nastavení síťové knihovny.
- OTA partition tabulka musí být vhodná pro fyzickou flash: na 4MB ESP32
  použijte `min_spiffs.csv`, první přechod na nové rozložení flash musí
  být proveden přes USB a může vyžadovat vymazání původní konfigurace.
- Rollback OTA při nedokončené aktualizaci využívá možností ESP32
  platformy; není implementován vlastní systém automatického rollbacku.

## Fyzická akceptace
1. Pozorovat potvrzení UART handshake při startu a během Wi-Fi výpadků.
2. Zapnout BOOT AP a prokázat nepřerušovanou UART diagnostiku.
3. Ověřit pět režimů, teplotu, ventilátor, swing a nezměněné Modbus registry.
4. Zapnout MQTT+Discovery: objeví se jediná climate entita,
   režim HEAT z OFF opravdu zapne klimatizaci.
5. Nastavit v Capability Manageru svislý swing jako „nepodporováno“ a
   ověřit, že jej HA při další aktualizaci inzeruje správně.
6. Přepnout CS/EN v dashboardu i servisu, uložit jazyk a obnovit stránku.
7. Provést neúspěšný OTA upload a zkontrolovat obnovení Modbusu.
8. Exportovat a importovat JSON nastavení; hesla zůstanou zachována.
9. Porovnat Modbus diagnostiku (registry 100..112) proti `/api/metrics`.
10. Bez úspěšné HW akceptace ponechat PR jako draft.
